# Preprocess Formats And Contracts

This document describes the current preprocess output contracts written by `src.preprocess.pipeline`.

## Output Filenames

Preprocess outputs are named by dataset type and preprocess timestamp:

```text
preprocess-{preprocess_type}-{preprocess_timestamp}.npz
```

Examples:

```text
preprocess-orderbook-20260607.123456.npz
preprocess-trade-20260607.123456.npz
```

The path is generated by `src.dataset_artifacts.build_preprocessed_output_path(...)`.

The current pipeline writes one file per `preprocess_type` for each raw batch. For a given batch, the `orderbook` and `trade` outputs share the same `preprocess_timestamp`, which defaults to the raw CSV batch timestamp.

`preprocess_batch(...)` and `preprocess_batches(...)` also accept `trade_window_seconds`, a positive integer that controls the shared trade and orderbook bucket grid.

## Shared Metadata Contract

Every preprocess `.npz` file must contain these metadata keys:

- `preprocess_type`
- `preprocess_timestamp`
- `product_id`
- `timestamp`
- `file_stem`
- `available_views`

Additional metadata may be present depending on the dataset type:

- `depth`
  - Currently written only for the `orderbook` preprocess type.
- `orderbook_window_seconds_available`
  - Integer array listing every orderbook window version currently stored in the file.
- `orderbook_window_seconds_latest`
  - Integer value identifying the orderbook version written or overwritten most recently.
- `trade_window_seconds_available`
  - Integer array listing every trade window version currently stored in the file.
- `trade_window_seconds_latest`
  - Integer value identifying the version written or overwritten most recently.

## Dataset Types

### `orderbook`

The orderbook dataset no longer writes unsuffixed `time_axis`, `bid_price`, `bid_size`, `ask_price`, `ask_size`, `bid`, `ask`, or `mid` keys for new outputs. Instead, each requested `trade_window_seconds=N` version is stored under:

- `time_axis__w{N}`
- `bid_price__w{N}`
- `bid_size__w{N}`
- `ask_price__w{N}`
- `ask_size__w{N}`
- `bid__w{N}`
- `ask__w{N}`
- `mid__w{N}`

Example for `trade_window_seconds=5`:

- `time_axis__w5`
- `bid_price__w5`
- `bid_size__w5`
- `ask_price__w5`
- `ask_size__w5`
- `bid__w5`
- `ask__w5`
- `mid__w5`

Orderbook rows are produced by this fixed contract:

1. Normalize raw trade times and update times.
2. Compute the overlap between the trade time range and the level2 update time range.
3. Trim 1 second from the start and 1 second from the end of that overlap.
4. Start buckets at `ceil(trimmed_start)` so every bucket start is an integer second.
5. Emit only complete buckets satisfying `bucket_start + trade_window_seconds <= trimmed_end`.
6. For each bucket, replay all level2 updates with `update_time < bucket_start`.
7. Exclude updates at exactly `bucket_start` from that bucket.

`time_axis__wN` has shape `(bucket_count,)`.

`bid_price__wN`, `bid_size__wN`, `ask_price__wN`, and `ask_size__wN` have shape `(bucket_count, depth)`.

`bid__wN`, `ask__wN`, and `mid__wN` have shape `(bucket_count,)`.

Bid columns are ordered best-to-worse bid, and ask columns are ordered best-to-worse ask.

This contract also allows empty arrays for orderbook datasets. The orderbook builder writes a schema-valid windowed dataset even when the raw batch has no trades, no updates, no valid overlap, or no complete bucket after trimming.

The orderbook `.npz` is incrementally mergeable:

- Writing a new `N` appends orderbook `*__wN` keys without deleting other stored orderbook `*__wM` versions.
- Rewriting an existing `N` replaces only the matching orderbook `*__wN` keys.
- Legacy unsuffixed orderbook keys are dropped when a new windowed orderbook payload is merged into the file.

### `trade`

The trade dataset no longer writes unsuffixed `trade_time`, `trade_price`, `trade_volume`, or `trade_side` keys for new outputs. Instead, each requested `trade_window_seconds=N` version is stored under:

- `trade_time__w{N}`
- `trade_price__w{N}`
- `trade_volume__w{N}`
- `trade_side__w{N}`

Example for `trade_window_seconds=5`:

- `trade_time__w5`
- `trade_price__w5`
- `trade_volume__w5`
- `trade_side__w5`

Trade rows are produced by this fixed contract:

1. Normalize raw trade times and update times.
2. Compute the overlap between the trade time range and the level2 update time range.
3. Trim 1 second from the start and 1 second from the end of that overlap.
4. Start buckets at `ceil(trimmed_start)` so every bucket start is an integer second.
5. Emit only complete buckets satisfying `bucket_start + trade_window_seconds <= trimmed_end`.
6. Aggregate volume within each bucket by `(bucket_start, price, side)`.
7. Sort the output rows by `(bucket_start, price, side)` ascending.

Buckets use a half-open interval: `[bucket_start, bucket_start + trade_window_seconds)`.

This contract also allows empty arrays for trade datasets. `src.preprocess.trade._empty_trade_payload()` writes a schema-valid windowed dataset even when the raw batch has no trades, no updates, no valid overlap, or no complete bucket after trimming.

The trade `.npz` is incrementally mergeable:

- Writing a new `N` appends `trade_*__wN` without deleting other stored `trade_*__wM` versions.
- Rewriting an existing `N` replaces only the matching `trade_*__wN` keys.
- Legacy unsuffixed trade keys may still exist in older files and are preserved as-is by the current merge path.

## `available_views`

`available_views` is the explicit view list stored in each preprocess file.

Current preprocess-produced view names are:

- `orderbook`
- `trades_scatter`
- `trade_volume_timeline`

The `trade` preprocess file continues to store `available_views = ("trades_scatter", "trade_volume_timeline")` regardless of how many window versions are present in the file.
The `orderbook` preprocess file continues to store `available_views = ("orderbook",)` regardless of how many window versions are present in the file.

## Discovery Contract

`src.dataset_artifacts.discover_preprocessed_artifacts(...)` expects preprocess files to satisfy both:

- The filename format parsed by `parse_preprocessed_filename(...)`.
- The required metadata fields stored inside the `.npz`.

If the metadata values do not match the filename values for `preprocess_type` or `preprocess_timestamp`, discovery rejects the artifact. Legacy `...mmm-seq.npz` filenames are not accepted.

## Cross-Module Coupling

When changing preprocess output contracts, keep these modules synchronized:

- `src/preprocess/pipeline.py`
- `src/preprocess/orderbook.py`
- `src/preprocess/trade.py`
- `src/dataset_artifacts/catalog.py`
- `result/convert_data.py`

`result/convert_data.py` writes preprocess artifacts for `trade_window_seconds` values `(1, 5, 10, 30)` from raw batches in `data/raw`.
