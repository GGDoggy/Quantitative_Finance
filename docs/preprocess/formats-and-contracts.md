# Preprocess Formats And Contracts

This document describes the current preprocess output contracts written by `src.preprocess.pipeline`.

## Output Filenames

Preprocess outputs are named by dataset type, preprocess timestamp, and sequence number:

```text
preprocess-{preprocess_type}-{preprocess_timestamp}-{seq_num}.npz
```

Examples:

```text
preprocess-orderbook-20260607.123456.789-3.npz
preprocess-trade-20260607.123456.789-3.npz
```

The path is generated by `src.dataset_artifacts.build_preprocessed_output_path(...)`.

The filename contract does not require one file per raw batch. Utility workflows may emit multiple preprocess files of the same `preprocess_type` for one source batch by incrementing `seq_num`.

## Shared Metadata Contract

Every preprocess `.npz` file must contain these metadata keys:

- `preprocess_type`
- `preprocess_timestamp`
- `seq_num`
- `product_id`
- `timestamp`
- `file_stem`
- `available_views`

Additional metadata may be present depending on the dataset type:

- `depth`
  - Currently written only for the `orderbook` preprocess type.

## Dataset Types

### `orderbook`

The orderbook dataset must contain at least:

- `price_axis`
- `time_axis`
- `data`
- `bid`
- `ask`

The current implementation also writes:

- `mid`

Shape and consistency requirements:

- `price_axis.ndim == 1`
- `time_axis.ndim == 1`
- `data.ndim == 2`
- `bid.ndim == 1`
- `ask.ndim == 1`
- `bid.shape == ask.shape`
- `data.shape[0] == time_axis.shape[0]`
- `bid.shape[0] == time_axis.shape[0]`
- `ask.shape[0] == time_axis.shape[0]`
- `data.shape[1] == price_axis.shape[0]`

Current construction notes:

- `data` contains only the union of visible bid/ask depth levels encountered during replay, not every price level present in the raw batch.
- Rows are still aligned to every replayed update timestamp in `time_axis`.
- `mid` is derived from `bid` and `ask` after replay completes.

Associated views:

- `orderbook`

### `trade`

The trade dataset must contain:

- `trade_time`
- `trade_price`
- `trade_volume`
- `trade_side`

Type expectations:

- `trade_time`
  - Stored as `datetime64[ns]`.
- `trade_price`
  - Floating-point array.
- `trade_volume`
  - Floating-point array.
- `trade_side`
  - Floating-point taker-side encoding from raw trade rows.

This contract also allows empty arrays for trade datasets. `src.preprocess.trade._empty_trade_payload()` writes a schema-valid dataset even when the raw batch contains no trade rows.

Associated views:

- `trades_scatter`
- `trade_volume_timeline`

## `available_views`

`available_views` is the explicit view list stored in each preprocess file.

Current preprocess-produced view names are:

- `orderbook`
- `trades_scatter`
- `trade_volume_timeline`

Artifact discovery may also infer these views from payload keys when `available_views` is absent, but current preprocess writes the field directly and downstream code should treat it as the primary source of truth.

## Discovery Contract

`src.dataset_artifacts.discover_preprocessed_artifacts(...)` expects preprocess files to satisfy both:

- The filename format parsed by `parse_preprocessed_filename(...)`.
- The required metadata fields stored inside the `.npz`.

If the metadata values do not match the filename values for `preprocess_type`, `preprocess_timestamp`, or `seq_num`, discovery rejects the artifact.

## Cross-Module Coupling

When changing preprocess output contracts, keep these modules synchronized:

- `src/preprocess/pipeline.py`
- `src/preprocess/orderbook.py`
- `src/preprocess/trade.py`
- `src/dataset_artifacts/catalog.py`
- `test/test_preprocess_orderbook.py`
