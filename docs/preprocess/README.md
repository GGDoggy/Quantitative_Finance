# `src.preprocess`

`src.preprocess` converts a `RawBatch` from `src.raw_batches` into one or more preprocessed `.npz` datasets that downstream discovery and visualization code can consume.

- [formats-and-contracts.md](formats-and-contracts.md)
- [module-reference.md](module-reference.md)

## Scope

The current preprocess package contains:

- `src/preprocess/__init__.py`
  - Re-exports the supported preprocess API surface for callers.
- `src/preprocess/pipeline.py`
  - Orchestrates batch loading, builder execution, metadata injection, and `.npz` writes.
- `src/preprocess/orderbook.py`
  - Builds orderbook history arrays from raw level2 snapshots and updates.
- `src/preprocess/trade.py`
  - Builds trade arrays from raw trade rows.
- `src/preprocess/exceptions.py`
  - Defines preprocess-specific exception types.

## Data Flow

```text
RawBatch
  -> load_raw_batch()
  -> build_preprocess_context()
  -> PreprocessContext
  -> PLOT_REGISTRY builders
  -> payload dictionaries
  -> preprocess-{type}-{timestamp}-{seq}.npz
  -> src.dataset_artifacts.discover_preprocessed_artifacts()
```

## Current Outputs

The preprocess pipeline currently writes two dataset types:

- `orderbook`
  - Provides the `orderbook` view.
- `trade`
  - Provides the `trades_scatter` and `trade_volume_timeline` views.

Each dataset type is written as a separate `.npz` file. A single raw batch therefore produces multiple preprocess files that share the same preprocess timestamp and sequence number.

## Public API

The public API exposed by `src.preprocess.__init__` is:

- `DEFAULT_DEPTH`
- `PLOT_REGISTRY`
- `PreprocessContext`
- `PreprocessBuilderSpec`
- `preprocess_batch(...)`
- `preprocess_batches(...)`
- `PreprocessError`
- `PreprocessValidationError`

## Important Behavior

- `preprocess_batch(...)` loads one `RawBatch`, runs every registered builder in `PLOT_REGISTRY`, and writes one file per successful builder.
- `preprocess_batches(...)` reuses a single generated preprocess timestamp across the whole batch run and increments `seq_num` per raw batch.
- Output file names are generated by `src.dataset_artifacts.build_preprocessed_output_path(...)`.
- Generated preprocess timestamps use `PREPROCESS_TIMEZONE = Asia/Taipei`, while raw batch timestamps still come from the raw filename.
- Only the `orderbook` dataset currently stores `depth` metadata.
- The `trade` dataset is still written when a batch has no trades; its payload contains empty typed arrays.
- View availability is stored explicitly in each `.npz` file through the `available_views` field.

## Relationship To Other Packages

- `src.raw_batches`
  - Supplies `RawBatch`, `LoadedRawBatch`, discovery, and CSV loading.
- `src.dataset_artifacts`
  - Owns preprocess file naming, metadata parsing, and artifact discovery.
- `src.simulation`
  - Produces separate simulation `.npz` artifacts that can later be attached to discovered preprocess artifacts.

## Maintenance Notes

- If a new preprocess dataset type is added, update `PLOT_REGISTRY`, this documentation directory, and any artifact discovery assumptions together.
- If required payload keys or view names change, keep `src.preprocess`, `src.dataset_artifacts`, tests, and docs synchronized.
